# Operations Duty Roster

为小型运维团队生成并核查值班安排。仅使用 Go 标准库，不接入日历或通知服务。

## 构建与运行

```sh
go build -o roster .

# 生成排班（无可行方案时以非零状态退出并说明原因，不输出缺人排班）
./roster generate -input problem.json -output plan.json

# 独立核查外部方案是否满足全部约束
./roster verify -input problem.json -plan plan.json

# 对两个已分配班次交换人员，重新检查全部约束与固定分配
./roster swap -input problem.json -plan plan.json -shift-a S1 -shift-b S2 -output newplan.json
```

## 输入格式

```json
{
  "minRestMinutes": 480,
  "people": [
    {
      "id": "alice",
      "qualifications": ["network", "database"],
      "unavailable": [{"start": "2026-10-03T00:00Z", "end": "2026-10-03T06:00Z"}],
      "maxMinutes": 720
    }
  ],
  "shifts": [
    {"id": "s1", "start": "2026-10-03T08:00Z", "end": "2026-10-03T12:00Z", "qualification": "network"}
  ],
  "fixed": [{"shift": "s1", "person": "alice"}]
}
```

校验规则：

- 最多 8 名人员、12 个班次；人员与班次标识必须唯一，引用（`fixed`、方案中的
  `person`/`shift`）必须有效。
- 时间统一为 UTC 且精确到分钟，格式为 `2006-01-02T15:04Z07:00`（如
  `2026-10-03T08:00Z`）；每个区间结束必须晚于开始。
- `minRestMinutes` 与 `maxMinutes` 必须为非负整数。

## 承接判定规则

人员只有在同时满足以下条件时才能承接一个班次：

- 具备该班次要求的资格；
- 班次区间与其全部不可用区间不相交；
- 与其已承担班次不重叠；
- 前班结束到后班开始（或反向）的间隔不少于 `minRestMinutes`，间隔恰好等于
  下限即为合法；
- 加上该班次后总时长不超过个人 `maxMinutes`。

所有区间一律按左闭右开 `[start, end)` 处理：不可用区间在班次开始时刻结束、
或两个班次首尾相接，都不算冲突。

## 排序与求解规则

- 班次按开始时间升序、再按班次编号字典序排序，求解与输出均遵循该顺序。
- 预先固定的分配（`fixed`）在生成时不得改变；固定分配自身违反约束时整体
  判定为无可行方案。
- 求解采用带回溯的深度优先搜索，不会因为一次贪心选择失败就断言无解。
- 在所有可行方案中，先最小化“个人总时长的最大值”，再取该前提下按班次
  顺序排列的人员编号序列字典序最小者。实现上先二分出最小可行的时长上限，
  再按人员编号字典序搜索首个完整方案。
- 无可行方案时明确报告错误并以非零状态退出，不输出缺人的排班。

## 输出格式

`generate` 与 `swap` 输出 JSON 方案：`assignments` 按排序后的班次顺序列出
每个班次的承接人，`summary` 汇总每人的总时长与所承担班次。

## 换班规则

`swap` 针对已分配的两个班次交换承接人，随后对**全部**约束（资格、不可用
区间、重叠、休息、时长上限、固定分配）重新核查，而不是只检查两个班次是否
重叠。核查失败时原方案文件保持不变并以非零状态退出；成功时写出新方案并
在标准输出打印变更说明（哪个班次由谁换给谁）。

## 测试

```sh
go test ./...
```

覆盖需要回溯的安排、休息时长边界、半开区间、目标排序、固定分配、资格不符
的换班以及换班失败时原方案保持不变等场景。
